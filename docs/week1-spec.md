# Спецификация JSON CLI

## Назначение
CLI читает JSON-файл с данными компании, проверяет записи сотрудников
и выводит очищенный список корректных сотрудников.

## Входные данные
Программа получает путь к JSON-файлу в кодировке UTF-8.

Корневое значение JSON должно быть объектом.
В корневом объекте обязательно должно быть поле `employees` со значением-массивом.

## Правила проверки записи сотрудника
Каждый элемент массива `employees` должен быть JSON-объектом.

Для каждого сотрудника обязательны поля `id`, `firstName` и `lastName`.

Каждое обязательное поле должно:
- существовать;
- быть строкой;
- после удаления пробелов по краям содержать хотя бы один символ.

Если хотя бы одно правило нарушено, запись считается некорректной.

## Очищенный результат
Для каждой корректной записи программа создаёт новый объект только с полями:
`id`, `firstName`, `lastName`.

Пробелы по краям значений удаляются.
Поле `salary` и другие исходные поля в результат не включаются.
Исходный JSON-файл не изменяется.

## Ошибки
Если JSON не удаётся прочитать из-за неверного синтаксиса, программа выводит понятное сообщение и завершает работу.

Если корневой JSON не является объектом, поле `employees` отсутствует
или `employees` не является массивом, программа выводит понятное сообщение и завершает работу.

Если отдельная запись сотрудника некорректна, программа:
- не включает её в очищенный результат;
- продолжает проверку остальных записей;
- выводит сообщение с номером записи в массиве `employees` и названиями нарушивших правила полей.

Номер записи показывается начиная с 1.

## Критерии приёмки
1. Для корректного файла с десятью корректными сотрудниками программа выводит десять очищенных записей. В каждой есть только `id`, `firstName` и `lastName`; поля `salary` нет.

2. Для файла, в котором у второго сотрудника пустое `lastName`, программа не выводит этого сотрудника, выводит остальных корректных сотрудников и сообщает, что в записи №2 некорректно поле `lastName`.

3. Для файла без поля `employees` программа не выводит очищенные записи и сообщает, что обязательное поле отсутствует.

4. Для файла с неверным JSON-синтаксисом программа не завершается аварийно, а выводит понятное сообщение об ошибке чтения JSON.
